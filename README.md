# mkon

**mkon** — формат конфигов для людей на основе [Hjson](https://hjson.github.io/) (но не совместимый с ним, см. ниже): расширение JSON, ориентированное на людей. Тот же JSON, но с комментариями, без обязательных кавычек у ключей, без запятых, с multiline-строками и терпимостью к мелочам вроде висячих запятых. Парсится в обычные JS-значения, сериализуется обратно в mkon.

Этот пакет — **парсер и стрингфаер mkon** с опциональной возможностью подключить Vite-плагин для импорта `.mkon` файлов прямо в сборку.

## Зачем mkon

- **Конфиги, которые читает человек.** JSON для машин, mkon для людей: комментарии, свобода форматирования, никаких лишних кавычек и запятых.
- **Обратная совместимость с JSON.** Любой валидный JSON — валидный mkon.
- **Комментарии.** Только JS-стиль: `//` и `/* */` — сохраняются через `keepWsc` и доступны через `getComment()`. `#` — обычный символ (`color: #fff`).
- **Специальные числа.** `NaN`, `Infinity`, `+Infinity`, `-Infinity`, `-0` читаются и пишутся как числа.
- **Даты.** ISO 8601 без кавычек (`2024-01-15`, `2024-01-15T10:30Z`) читается как `Date` и пишется обратно.
- **Без плагинов.** Смысл значения не зависит от настроек парсера: один и тот же файл везде читается одинаково.
- **Multiline-строки.** `'''...'''` для длинных текстов без экранирования.
- **Quoteless-строки.** Значения можно писать без кавычек.

### Где заканчивается quoteless-строка

> ⚠️ Отличие от Hjson: там quoteless-строка всегда тянется до конца строки, вместе с `,`, `}` и `]`.

Внутри `[...]`, `{...}` и корневого объекта без скобок quoteless-строка заканчивается:

- на конце строки;
- на `,`, `}` или `]`, если они не внутри скобок, открытых в самом значении.

```mkon
{ html: ⊄, latex: \not\subset, aliases: [notsub, notsubset] }
// → { html: "⊄", latex: "\\not\\subset", aliases: ["notsub", "notsubset"] }

[
  a, b, c
  d, e, f
]
// → ["a", "b", "c", "d", "e", "f"]

{ f: \frac{a,b}{c}, m: m[i, j] }
// → парные скобки внутри значения не разрывают его: { f: "\\frac{a,b}{c}", m: "m[i, j]" }
```

Если запятая — часть текста, значение нужно взять в кавычки: `"a, b"`, `'a, b'` или `'''a, b'''` (последний вариант без escape-последовательностей, удобен для `\` и LaTeX). `stringify` расставляет кавычки сам. Одиночное корневое значение (`Hello, world` как весь документ) по-прежнему читается до конца строки.

### Отличия от Hjson

| | Hjson | mkon |
|---|---|---|
| Quoteless-строка в `[...]` / `{...}` | до конца строки | до `,` / `}` / `]` (см. выше) |
| Комментарии | `#`, `//`, `/* */` | `//`, `/* */` |
| `a: #fff` | `a` = `""` + комментарий | `a` = `"#fff"` |
| `NaN`, `±Infinity` | строки; `stringify` пишет `null` | числа в обе стороны |
| `-0` | `stringify` пишет `0` | `-0` |
| `2024-01-15` без кавычек | строка (дата — только через dsf) | `Date` |
| Плагины форматов (`dsf`) | есть | нет: опция `dsf` — ошибка |

### Специальные числа

```mkon
{
  a: NaN
  b: Infinity     // или +Infinity
  c: -Infinity
  d: -0
  e: "NaN"        // строка: в кавычках литерал не распознаётся
  // строка: регистр важен
  f: nan
  // строка: литерал должен занимать всё значение
  g: Infinity war
}
```

> Комментарий на одной строке с quoteless-строкой — часть строки (`a: x // y` → `"x // y"`), поэтому выше он вынесен на отдельную строку. После чисел, дат, `true`/`false`/`null`, `NaN`/`Infinity` и строк в кавычках комментарий работает как обычно.

`stringify` пишет эти числа так же и сам берёт в кавычки строки, которые выглядят как литералы (`"NaN"`, `"-0"`, `"Infinity"`), так что round-trip не путает числа и строки. Vite-плагин тоже сохраняет их числами в сгенерированном модуле.

### Даты

ISO 8601 **без кавычек** читается как `Date`. Поддерживаются ровно две формы:

```mkon
{
  day: 2024-01-15                  // полночь UTC
  at: 2024-01-15T10:30Z            // часовой пояс обязателен: Z или ±HH:MM
  precise: 2024-01-15T10:30:45.123+03:00
  text: "2024-01-15"               // строка: в кавычках дата не распознаётся
  // строки: время без пояса, пробел вместо T, неполная дата
  local: 2024-01-15T10:30
  spaced: 2024-01-15 10:30Z
  short: 2024-1-5
}
```

- Время без часового пояса — строка: иначе результат зависел бы от пояса машины, на которой читают файл.
- Невалидная дата без кавычек (`2024-02-30`, `T25:00Z`) — ошибка парсинга, а не тихий перенос на март.
- `stringify` пишет `Date` в UTC: `2024-01-15` для полуночи, иначе `2024-01-15T10:30:00Z` (миллисекунды — только если не нулевые). Исходный часовой пояс не сохраняется, сохраняется момент времени.
- Строки, похожие на дату, `stringify` берёт в кавычки. Invalid Date и годы вне 0000–9999 — ошибка.
- Vite-плагин отдаёт даты как `new Date(...)`, в `.d.mkon.ts` у них тип `Date`.

### Гарантии round-trip

`parse(stringify(x))` возвращает те же данные — это проверяется на случайных данных в обоих языках. Для этого `stringify`:

- пишет строки с `\r` в кавычках, а не в `'''` (внутри `'''` читатель выбрасывает `\r`);
- не использует однострочную форму `'''…'''` для строк, начинающихся с пробела или таба (читатель пропускает пробелы после `'''`);
- берёт в кавычки корневую строку с `:` (иначе она прочиталась бы как корневой объект без скобок);
- всегда ставит блочный `'''` значения объекта на отдельную строку, даже с `bracesSameLine`: отступ блока читатель берёт из колонки `'''`, и на одной строке с ключом содержимое съезжало (с `space: 4` портилась каждая многострочная строка).

**Числа — IEEE-754 double**, как в JSON. Целые за пределами ±(2⁵³−1) теряют точность во всех реализациях одинаково.

## Реализации и общие тесты

- **mkon-js** (этот пакет) — эталон.
- **mkon_py** — Python-реализация, побайтово совпадающая с этой (те же тексты, те же данные).

Общий набор тестов для всех реализаций:

- `test/assets/` — фикстуры (`*_test.*`, `*_result.mkon`, `*_result.json`);
- `test/conformance/cases.json` — кейсы с входом и ожиданиями; значения — в «tagged JSON» (`{"$number": "NaN"}`, `{"$date": "…"}`, см. `test/conformance/tagged.js`).

Если меняется поведение, ожидания пересчитываются по эталону, а дифф показывает, как изменился стандарт:

```bash
npm run conformance:update   # пересчитать cases.json по текущей реализации
git diff test/conformance/cases.json
```

После этого в mkon_py: `python scripts/sync_conformance.py` и `python -m unittest discover -s tests` (там же кросс-проверка с живой JS-реализацией).

## Базовое использование

```js
import { parse, stringify } from 'mkon'

const data = parse(`
  // комментарий
  name: mkon
  version: 3.0
  features: [
    human-friendly
    json-compatible
  ]
`)

const text = stringify(data, { space: 2, quotes: 'min' })
```

## API

### `parse(source, opt)`

| Опция | Тип | По умолчанию | Описание |
|-------|-----|--------------|----------|
| `keepWsc` | `boolean` | `false` | Сохранять комментарии и whitespace (WSC). Доступны через `getComment()`. |

### `stringify(data, opt)`

#### Форматирование

| Опция | Тип | По умолчанию | Описание |
|-------|-----|--------------|----------|
| `eol` | `'\n' \| '\r\n'` | `EOL` | Символ конца строки. |
| `space` | `number \| string` | `'  '` | Отступ: число пробелов или готовая строка. |
| `bracesSameLine` | `boolean` | `false` | Открывающая `{`/`[`/`'''` на одной строке с ключом. |
| `emitRootBraces` | `boolean` | `true` | Оборачивать корневой объект в `{}`. Если `false` — скобки убираются. |
| `separator` | `boolean` | `false` | Добавлять запятые между элементами. Кавычки ставятся по тем же правилам, что и без запятых. |
| `multiline` | `'std' \| 'no-tabs' \| 'off'` | `'std'` | Режим multiline-строк (`'''`): `std` — табы разрешены; `no-tabs` — табы экранируются; `off` — multiline отключён. |
| `condense` | `number` | `0` | Порог схлопывания объекта/массива в одну строку. `0` — выключено. |

#### Кавычки

| Опция | Тип | По умолчанию | Описание |
|-------|-----|--------------|----------|
| `quotes` | `'min' \| 'keys' \| 'strings' \| 'all'` | `'min'` | Режим кавычек (см. таблицу ниже). |
| `quoteChar` | `'"' \| "'"` | `'"'` | Символ кавычек. |

#### Комментарии и порядок

| Опция | Тип | По умолчанию | Описание |
|-------|-----|--------------|----------|
| `keepWsc` | `boolean` | `false` | Сохранять комментарии/whitespace при сериализации (из `getComment(data)`). |
| `sortProps` | `boolean` | `false` | Сортировать ключи объекта по алфавиту. |

#### Прочее

| Опция | Тип | По умолчанию | Описание |
|-------|-----|--------------|----------|
| `colors` | `boolean` | `false` | ANSI-раскраска вывода (для терминала). |

### Режимы `quotes`

| Режим | Ключи | Строки | Комментарий |
|-------|-------|--------|-------------|
| `'min'` (дефолт) | кавычки только если обязательны | кавычки только если обязательны | минимально возможное число кавычек |
| `'keys'` | все в кавычках | только если обязательны | |
| `'strings'` | только если обязательны | все в кавычках | |
| `'all'` | все в кавычках | все в кавычках | |

## Vite-плагин (опционально)

Плагин позволяет импортировать `.mkon` файлы напрямую в Vite-сборку. Это **дополнение** к парсеру, а не его замена: сам mkon-функционал живёт в `parse`/`stringify`, плагин лишь встраивает чтение `.mkon` в бандлер с query-параметрами для трансформации.

### Подключение

```js
import mkon from './vite-plugin-mkon.js'

export default {
    plugins: [
        mkon({
            handlers: {
                // именованные обработчики
            },
            default: null, // имя handler'а по умолчанию
        }),
    ],
}
```

### Использование

```js
import data from './file.mkon'
import config from './file.mkon?as=config'
import picked from './file.mkon?pick=a.b,c.d'
import omitted from './file.mkon?omit=a.b,c.d'
import combined from './file.mkon?as=config&pick=a.b,c&omit=d'
```

### Query-параметры

| Параметр | Описание |
|----------|----------|
| `as=<name>` | Применить handler с указанным именем из `options.handlers`. |
| `pick=a.b,c.d` | Оставить только указанные пути. Один путь — вернуть значение, несколько — объект `{ "a.b": ..., "c.d": ... }`. |
| `omit=a.b,c.d` | Исключить указанные пути (глубокая копия без мутации оригинала). |

Порядок применения: `as` → `pick` → `omit`.

### Опции плагина

| Опция | Тип | По умолчанию | Описание |
|-------|-----|--------------|----------|
| `handlers` | `Record<string, Function>` | `{}` | Именованные обработчики значения до применения `pick`/`omit`. Сигнатура: `(value, params, { file, ctx }) => any`. |
| `default` | `string \| null` | `null` | Имя handler'а по умолчанию, если в import не указан `?as=...`. |
| `dts` | `boolean` | `true` | Генерировать типы для импортов `.mkon` (см. ниже). |

### Типы для TypeScript

Рядом с каждым `file.mkon` плагин пишет `file.d.mkon.ts` с типом значения, которое даёт импорт **без query** (с учётом `default`-handler'а):

```ts
// config.d.mkon.ts — сгенерировано
declare const value: {
    server: {
        host: string
        port: number
    }
}
export default value
```

Чтобы TypeScript находил такие файлы, в `tsconfig.json` нужно включить:

```json
{ "compilerOptions": { "allowArbitraryExtensions": true } }
```

Объявление пишется (и обновляется) при каждом импорте файла — в `vite build` и `vite dev`; в dev-режиме ещё и при изменении `.mkon`. Файлы, которые никто не импортирует, плагин не трогает. Поэтому для нового `.mkon` объявление появится после первого запуска сборки или dev-сервера. Типы расширяются как у JSON-импортов: `'a'` → `string`. Объекты в массивах сливаются, ключи, которые есть не у всех элементов, становятся необязательными.

Импорты с query (`?pick=`, `?as=`, `?omit=`) так не типизируются: TypeScript не умеет сопоставить модулю с query отдельный файл объявления. Для них по-прежнему нужно `declare module '*.mkon?*'` или явное приведение типа.

### Обработка ошибок

- Неизвестный handler — `this.error('[mkon] unknown handler "..." in <file>')`.
- Путь не найден при `pick` — `this.error('[mkon] path "..." not found in <file>')`.

### Ограничения плагина

- Значения сериализуются через `JSON.stringify`, поэтому функции, `undefined`, `Symbol`, `BigInt` и циклические ссылки не поддерживаются.
- `omit` делает глубокую копию через `JSON.parse(JSON.stringify(...))` — теряются типы, не представимые в JSON.
- Плагин читает файл синхронно (`fs.readFileSync`).
- `enforce: 'pre'` — обработка `.mkon` происходит раньше других плагинов Vite.
